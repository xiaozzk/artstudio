# 调研笔记：参考实现分析与法袍法师包实测（2026-09-24）

本笔记是 task/002 的设计依据。来源：两个外部参考仓库（`docs/spine-animation-ai/`、
`docs/Spine-AI-Generator/`，本地不入库）通读 + `tmp/法袍法师/` 交付包实测。

## 一、两个参考项目的动画实现哲学

### spine-animation-ai（Claude Skill，LLM 创作派）

- 全链路：拆件（Gemini 出解构图 + OpenCV 连通域切件）→ SIFT+RANSAC 定位 → 建骨 →
  **LLM 手写关键帧** → 打图集 → 预览。
- 动画部分零算法：LLM 按 12 原则直接写 Spine 4.2 JSON 时间轴（bezier 曲线 +
  相位错峰 follow-through + 幅度梯度大骨大幅）。
- 修正闭环值得抄：adjustment JSON 三元组 `original / user_delta / final`——
  可复核、可回退、可叠加成版本链；未改的件也强制记零 delta（"确认过"≠"漏了"）。

### Spine-AI-Generator（本地流水线，出厂自检派）

- 哲学相反：**AI 零参与动画**。`generateAnimations`（server/api/generator.js）只产
  一个 idle（root 正弦浮动 + 子部件错相位小幅旋转 ≤1.5°），曾有的 wave 调试动画
  被砍——"美术要别的动作，在 Spine 编辑器里照 idle 的写法加"。
- 注释踩坑库（直接翻译成本任务校验器断言）：
  1. 旋转键名按版本：3.8 = `angle`，4.0+ = `value`；写错运行时**静默不动**
  2. `curve:'smooth'` 非法（只认 `stepped` / 贝塞尔数组），解析直接出问题
  3. `translate` 是相对 setup pose 的偏移，写绝对坐标 → 角色平移出画面
  4. 拼合式切图旋转 >1.5° 接缝即露（对**纯拼合件**成立；我们的交付包同理要小心，
     mesh 件不受此限）
- **Spine CLI 反转**：`Spine -i x.json -o x.spine --to <名> -r` 官方 headless 把
  runtime JSON 转成可编辑工程（需已激活编辑器；.spine 格式跨小版本字节不同，
  永远不要手写，显式版本不回退）。

### 渲染层（"json+图集直接渲"的两条实现）

| | 方案 | 取舍 |
|---|---|---|
| spine-animation-ai | `generate_spine_player.py`：官方 `@esotericsoftware/spine-player` CDN + `rawDataURIs` 全 base64 内嵌单文件 | 语义 100% 保真、零维护；**CDN 版本要对齐包版本**（脚本写死 4.2.*，法袍法师 4.3.26 需改 4.3.*） |
| Spine-AI-Generator | `web/renderer.js`（750 行 Canvas 2D 自研）：手写 .json/.skel 解析 + region 变换 + **LBS mesh 蒙皮** + 30fps 采样对齐编辑器 | 动机：产物是散件 PNG，为预览先打 atlas 反馈太慢；只覆盖 bone 通道动画（无 deform/clip/blend） |

顶点坐标"，Σ 权重 × 各骨骼变换，基准搞错静止姿势就拼不回原图。

**本任务选型：官方 player 单文件**。交付包动画只写 bone 通道时自研层也够，但

### 关键帧语法共性（B1 模板格式的设计输入）

1. **99% linear + 少量 stepped，零贝塞尔**——平滑和震颤全靠关键帧密度。
   与 Spine-AI-Generator「密度换平滑」注释哲学撞车 = 行业实际做法。
2. 每骨每动作只占一条通道（rotate 或 translate 或 scale），无叠加。
3. 眨眼 = 标准三帧 scaleY 挤压（如 0.43/0.47/0.53）。
4. 时长全是 30fps 整帧数（0.67s=20 帧、1.33s=40 帧、2s=60 帧）。
5. 循环动画末帧回零（与 setup pose 无差，可任意切换）。
6. **解析陷阱**：4.3 JSON 首帧省略 `time`（缺省 0）；rotate 读 `value`。

## 三、结论

模板格式可以极端简化：`{ duration, tracks: { "<骨>.<通道>": [[t, v]...] } }`，
迁移 = 语义映射表（每包一张）+ 幅度按骨长缩放。法袍法师包即为第一个模板源
与第一个回环验证对象。

## 五、朝向统一功能（2026-09-25 goal-round）

**根因**：v1 映射表按画面位置映射左右。两包朝向相反（法袍朝左/络腮胡朝右，
以复原预览图为准），但骨架局部朝向几乎相同（arm_l1 243.6° ≈ bone6 242.3°）——
同增量在朝右角色身上视觉方向相反，变成「朝背后挥剑」。

**工具**：`tools/spine/anim/spine_flip.py`（JSON 级水平镜像）。
- 数学：X 轴镜像共轭 M·T·M → 局部 x/-rot；region 加 scaleX=-1 翻贴图；
  mesh 顶点 x 取负 + triangles 绕向反转；动画 translate.x/rotate.value 取负。
- `--check` 双翻回原文自检（法袍+络腮胡都过）。
- 自检抓出两个 bug：①加权顶点骨段步进错位（4 值/段：索引+x+y+权重，
  第一版 i+=2 错位到权重位）②scaleX 缺省归一化（原没写 vs 翻回来 1.0）。
- 边界：含 IK/constraints 报错退出（64/105 包含 IK）；slots/attachments/
  drawOrder 通道告警保留。

**流程改法（SKILL.md 阶段 0.5）**：朝左包 flip 成朝右 → render_rig 渲染 +
agent 看图确认 + player 验证 → 映射按角色语义（左手↔左手）写 → 迁移。
flip 后骨骼 setup 朝向变号，retarget 符号检测自动适配（v2 翻转 8 轨）。

**v2 结果**：attack 挥剑方向与面向一致（蓄力扛剑→高举→下劈连贯）；
death 向后侧翻倒地正确。小瑕疵：death 里影子（Shadow）未跟身体位移，
待查 translate 镜像符号。

### 5.1 translate 坐标系的正确模型（2026-09-25 二修）

death 里影子不跟人走 → 第一反应是「影子位移是世界系，别旋转」，加白名单跳过旋转。
**这是误诊**：Spine 的 translate 时间轴值活在**父骨骼坐标系**里，正确换算是

    v_A = R(θ_parentB − θ_parentA) · v_B        （θ 取父骨骼 setup 世界朝向）

- 影子：源父 root(0°) → 目标父 bone(90°) ⇒ 旋转 −90°：
  `(-69.66, 2.96) → (2.96, 69.66)`；换算回世界位移仍是 `(-69.7, 3.0)` ✅
- 白名单「不旋转」会得到 `(-69.66, 2.96)`，在 90° 的父空间里 = 世界**向下**移
  —— 错得更隐蔽。

**回归判据（客观、比肉眼强）**：逐帧把 translate 用 `R(父世界朝向)·v` 换成世界位移，
源与产物应逐帧相等。实测 death 的 Shadow/body_2/arm_l2 全 ✅（误差 <0.05）。

教训与 §二同源：**别凭"看着像"下结论，换算成不变量再比。**

### 5.3 flip 的 deform 镜像（2026-09-25 用户要求「两包都改朝左看效果」时查出）

用户要求把两包都改成朝左放 tmp 里看效果，翻络腮胡时发现 skill1 的
`animations.attachments.default.wq2.wq2.deform` 有**网格顶点位移**（武器形变），
而 flip 原先只对 bones/附件做镜像、**漏了 deform** ⇒ 朝左包里武器形变会歪向错的一侧。

修法（spine_flip.py）：deform 每帧 `vertices` 的 (x, y) 偏移对只取负 x、y 不动；
4.3 在 `animations.<名>.attachments.<皮肤>.<槽位>.<附件>.deform[]`、
3.8 在 `animations.<名>.deform[]`，两级都认。实测 10 顶点形变 x 全取负、y 不变 ✅，
双翻回原文自检仍通过。

顺带定论：`slots`（附件切换）与 `drawOrder`（层序偏移）**不需要镜像**——
附件名不变、镜像不改变相对深度关系，原先"告警保留"的担心是多余的（保留正确）。

法袍法师无 mesh/deform，故迁移产物不受此 bug 影响。

### 5.4 朝向判定的约定冲突（2026-09-25，重要教训）

用户看 `tmp/facing-left/法袍法师`（= 原包方向）后说「法师还是朝右」。
图像比对确认：用户截图 = **原包方向**（直接匹配 25.6 / 镜像后 35.3）。

两件事：

1. **我的操作错误**：上一轮我把法袍从 **`input/法袍法师-flipped`（已翻过的副本）**
   又翻了一次 ⇒ 等于转回原样，用户自然看不到变化。
   **规矩：换朝向一律以原始包为输入**（或用 `--from` 明确声明当前朝向）。
2. **左右语义不能由我硬编码**：我的读图判断与用户约定相反（用户视原包方向为"朝右"）。
   判定朝向本质是**业务约定 + 视觉判断**，工具不该内置语义。

因此给 `spine_flip.py` 加的方向配置（用户问的"有办法配置到向左吗"）：

```bash
spine_flip.py <包> -o <out> --from right --to left   # 声明当前/目标朝向；相同则不翻
spine_flip.py <包> --detect                          # 眼骨启发式线索（仅 17/105 包有眼骨）
spine_flip.py <包> -o <out>                          # 不给参数 = 默认镜像一次
```

交付方式也改：**两个方向各产一份**（`<包>-原包方向/` 与 `<包>-镜像方向/`），
附并排对比图（`_compare/`），由用户指认哪侧是"朝左"，再把默认值固化进流程与文档。

⚠ 顺带核实：`render_rig.py` 的渲染与 `复原预览图`（美术基准）**同向**，渲染器没有镜像 bug；
但它的字体回退列表原先指向本机不存在的 PingFang.ttc，已修（改用 Hiragino Sans GB 等）。
