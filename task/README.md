# task/ — 任务档案

**每个子任务一个文件夹**：一个任务的目标 / 验收 / 产出 / 决策全部收在它自己的目录里。
本目录**入库**（git 跟踪，口径同 `docs/`），是可长期翻阅的任务台账。

> 与 `tmp/` 的区别：`tmp/` 放**可再生的中间产物**（草稿、预览、临时下载、浏览器 profile 副本），不入库、可随时清；
> `task/` 放**要留档的任务本体**，入库、别随手清。

## 命名

```
task/NNN-短横线-slug/
```

- `NNN`：三位数字编号，从 `001` 起，**顺序递增、只加不改、绝不复用** —— 任务即使放弃，号也留着。
- `slug`：小写英文 + 数字 + 短横线，2–4 个词，说清「做什么」：`001-spine-reskin`、`002-eva-outfit-swap`。
- **不要**用中文、空格、下划线或日期；日期写在 `TASK.md` 里，不进目录名。

## 一个任务文件夹里放什么

| 路径 | 必需 | 内容 |
|------|------|------|
| `TASK.md` | ✅ | 任务说明：目标 / 验收标准 / 状态 / 产出 / 步骤 / 决策。模板见 `_template/TASK.md` |
| `input/` | | 该任务专用的输入（参考图、规格、抓来的数据…） |
| `output/` | | 交付产物；大二进制（图 / psd / 模型 / 归档 / 音视频）走 Git LFS |
| `notes/` | | 过程记录、调研、失败尝试 —— 可随时追加 |

小任务不必凑齐子目录：**只有 `TASK.md` 也完全合规**；等真有东西了再建 `input/` `output/` `notes/`。

## 新建一个任务

1. **取号**：看一眼现有目录，用最大编号 +1（空号不复用）。
2. **复制模板**：`_template/` → `NNN-slug/`。
3. **填 `TASK.md`**：目标、验收标准、状态先写「规划中」。
4. **在下表补一行**，让台账和目录对得上。
5. 开工把状态改「进行中」；收尾时补齐「产出」清单，改「已完成」。

## 与其它目录的分工

- 跨任务复用的脚本 → `tools/`；跨任务复用的文档 → `docs/`；**任务自己的东西留在 `task/NNN-slug/`**，别散到工作区根。
- 过程性的临时文件仍然写 `tmp/`，**不要**留在 `task/` 里冒充交付物。
