# 009 · modular 换装 + 种族一等公民

> **状态**：**方案已定，待开工**（2026-10-14 与用户逐条对齐）
> **前置**：007（体形 morph 管线，已完成）、008（Godot 快预览工坊，已完成）
> **契约**：[`assets/3d/rig/SPEC.md`](../../assets/3d/rig/SPEC.md)｜[`SKELETON.md`](../../assets/3d/rig/SKELETON.md)｜[`GENERATION-GUIDE.md`](../../assets/3d/rig/GENERATION-GUIDE.md)

## 1. 目标

把体形 morph 从「**固定套装**（007 的 B2：每套服装 = 一个自包含角色）」升级为
「**跨套件混搭**（modular：一具权威身体 + N 件可自由显隐的部件）」，并把**种族**做成**一等公民**，
为后续**自研 / AI 生成素材**定下可执行的契约。

**为什么必须改路线**：007 的 B2 结构上做不了"换装混搭"与"脱衣见身" ——
它的每套服装**自带**自己那份皮肤与骨架，"身体"这个概念在交付物里不存在。要混搭就必须有**一具权威身体**。

## 2. 已定方案（D1–D10，逐条与用户对齐）

| # | 决策 | 依据 / 代价 |
|---|---|---|
| **D1** | **路线 = B1-modular**：一具**权威身体**（完整皮肤 + 权重覆盖全部体形骨 + 承载骨架）+ **N 件可显隐部件** | 007 的 4 套 B2 **保留并存**为"固定套装"产品，不改动 |
| **D2** | **种族（race）做成一等公民**；`child` **也是种族**（本次**后置**，之后做） | 好处：child 自动获得独立的 rest/系数/包络/部位表，**零特例代码** |
| **D3** | 种族内**分男女（sex）**；**男女共用一副骨架** —— **一族一份 rest**，两性网格都绑到它 | ⚠ 现有资产的男女骨架是**两套各自独立做的**（实测骨长比离散度 **0.157**、最大 **1.89×**），**不继承** |
| **D4** | 骨架用 **`skeleton_profile` 抽象**：人形系（人形/精灵/恶魔/哥布林/海族/兽人/child）**共用一个 profile**；异形系（半人马/虫族/野兽）各一个 | 共用 profile → **动画可跨族复用**（只换 rest）。**若每族一套骨架，动画就无法复用** |
| **D5** | **VRM 角色词表定为「语义层标准」**；**骨名保持现状**（UE Mannequin 风格），**不改名** | 见 `SKELETON.md` **§6**（决策与三条理由）与 **§7**（IK 与 morph）；映射产物 `assets/3d/rig/skeleton_mapping.json`（52 映射 + 13 额外 = 65，**VRM 必需角色 15/15**）。**不改名**的理由：VRM 词表**覆盖不了生产骨架的全部**（无 `root`/IK/twist/叶子标记）→ 必然混用；且 24/24 资产、全部脚本与验收判据都建在现有骨名上 |
| **D6** | **身高 = 角色根节点等比缩放**（`h∈[0.90,1.10]`），**不碰骨 pose、不做 morph**；**儿童独立建模**，不走身高滑块 | 与身形**天然正交**。⚠ 等比会连带放大头（±10%），可接受 |
| **D7** | **头模不含脖子**（接缝画在颅底/下颌，**脖子归身体**） | 头→**100% 静态**、可**跨体型跨族复用**（实测头网格只有 11.5% 顶点动、≤0.43 cm，动的正是脖子过渡区） |
| **D8** | **层（layer）× 部位（region）两轴**；层序是**数据**不是硬编码 | 源包只有"部位"轴（Arms/Body/Legs/Feet/Head/Acc）→ **叠穿（衬衫+外套）它表达不了**，层轴是本任务新增 |
| **D9** | ⚠ **烘 morph 前必须清掉 IK / 全部约束** | pose 与 shape key 是**两套独立形变来源、会叠加**（实测读到过 **33 mm 假差**）→ 不清会把姿态错误烘进 morph |
| **D10** | 现有 4 套 B2 **不收编进种族体系** | 它们裁在 **Regular 身体**上，而**源包只有 Superhero**（已查明）→ 收编 = 把 Regular 衣套到 Superhero 体 = **A 路线**（实测 **74% 裸露**） |
| **D11** | **头身比 = 8 头**（实测锚定） | 现有库实测 **女 8.02 / 男 8.16 头**（SPEC **F34**）→ 取 8 与**整套既有资产比例兼容**，且留出向下的种族阶梯。⚠ **头身比决定头资产高度**（1.75 m 下 8 头 21.9 cm vs 7 头 25 cm）→ **头必须按族打标签** |
| **D12** | **身高：男 1.75 m / 女 1.70 m**；**rest 骨架基准 = 1.75**（一族一份 rest，男女共绑） | 女性网格 1.70 落在同一副骨上 → 几何偏差 **−2.86%**，对形变质量无实质影响。身高滑块 `h∈[0.92,1.08]` 缩放**角色根节点** |
| **D13** | **层 = 5 层定义**：`0 身体 / 1 基础层 / 2 内层 / 3 外层 / 4 配件`；**部位表 = 6 项**（body/arms/legs/feet/head/accessory） | 部位表**只对人形系有效** —— `region` 是**种族级**属性（`centaur` 会逼出「不能硬编码 Legs」），留到 P3 压力测试 |
| **D14** | **骨架 profile v2 = `humanoid_biped_7spine`（77 骨）**：脊柱 **3 → 7 节**、**每指加掌骨**（`palm_{index,middle,ring,pinky}_*`；**拇指不加**掌骨） | 借第三方件 Bodiez 的**结构优点**（躯干比例/弯曲更细腻、抓握更自然）。⚠ **索引是硬契约、定了不好改** → 趁「自己生成身体」这个时点一次改到位。产物：`profiles/humanoid_biped_7spine.json` + `tools/3d/skeleton/make_profile.py` |
| **D15** | **morph 通道 v2.0**：**预设轴**（`BS_Preset_Thin/Regular/Muscular/Fat`，**tent 连续插值**）+ **连续轴**（`BS_Hip_Wide` / `BS_Breast`）。⚠ **v2 不复用 v1 的任何通道名** | 借它的「多通道体型」（表达力远强于单轴胖瘦），但**改掉它的区间带硬切换**（拖动跳变）。同名不同义会**静默混用** → **换语义就换名字**。产物：`channels.json` |
| **D16** | **比例轴 = 骨缩放（沿骨轴）+ 身高归一化**；**不走 morph、不用约束** | ⚠ **glTF 里没有约束** → Bodiez 用 `ACTION` 约束做比例，**导出时全部消失**。而比例的本质就是骨长 → 骨缩放最自然，**零 morph 数据**，glTF 的 node scale **原生支持**；归一化让两条轴**由构造正交**（SPEC F36） |
| **D17** | **风格档 = ① 写实二次元（8 头）**；渲染走 **L1 卡渲 + L2 脸皮**，**不做面部 SDF、不做飘眉** | 只新增 **2 条契约**（ramp 图 + 描边平滑法线），**Godot 侧零 shader 可实现**。⭐ 硬规则：**身体不画死明暗**（它随体型变）、**脸可以**（它 100% 静态）。产物：`RENDER.md` |
| **D18** | 第三方件 Bodiez **只作参考分析，不引进生产资产**（即 **M2**：**自己生成身体**，只借鉴做法）。⭐ **滑块做法参考它** | ⚠ **不是许可问题** —— 它**有许可**。是**我们主动选自研**，因为自研能拿到「直接用它」给不了的三样：**统一骨架**（它男女分叉 74/71）、**我们自己的命名**（它是 Rigify 风格）、**可控拓扑与体积**（它男女拓扑不同 + SUBSURF 2 级）。而它最值钱的「做法」我们已全部吸收。产物：`reference/BODIEZ-ANALYSIS.md` |
| **D19** | **v1 资产（65 骨 + `BS_Thin`/`BS_Heavy`）冻结为 legacy 回归基线**，与新族**并存**、**不删** | 它是**已验证的回归基线**（38 项断言 / 13 项判据 / 逐位 digest / `run_check.py` 103/103 全跑在它上面）。删掉等于把验证链拆了 → **冻结保留**（同 007 对 B1 的处置） |
| **D20** | ✅ **渲染全量走 NPR**（卡渲 + 描边，L1+L2）；**不做 PBR 材质** | 三条理由：**① 风格**（二次元卡渲）**② 资源**（2 张图 vs 5 张）**③ ⭐ morph 兼容** —— PBR 的 Normal 贴图是为**原体型**画的，变胖后 UV 拉伸 → **高光/细节位置全不对**；而 NPR 的平色 + **ramp 实时算**没有这个问题。**理由 ③ 比风格更硬（是技术约束）。** 另：**AI 生成与 NPR 天然匹配**（AI 擅长的颜色/花纹正是 NPR 所需；PBR 需要的多图物理一致性恰是 AI 最弱的）。产物：`RENDER.md` §0 |
| **D21** | **皮肤区域在贴图里烤【中性白】**，肤色由 **`skin_tint` / `skin_lut` 参数**给 | **换肤色只改一个值**；且**脸与身体天然一致**（都在 87.5%H 接缝两侧，不能有色差）。⚠ **反悔窗口 = 现在 → 第一次烘图**（烘了要重做）。见 `RENDER.md` §6.6 |
| **D22** | **纹身/鳞片/伤疤走【贴图叠加】**，不做几何 | 关键机制：**`morph 只改顶点、完全不碰 UV`** ⇒ **贴图仍「焊」在表面上** ⇒ 自动跟随体型、零额外成本。⚠ 几何叠加要么不跟随（变胖后浮空/穿插）、要么通道翻倍。见 `RENDER.md` §6.7 |

## 3. 分阶段路线（**按风险排序，不按规模排序**）

| 阶段 | 做什么 | 验证哪一层抽象 |
|---|---|---|
| **P1** | **`humanoid` 一族**跑通完整 modular：权威身体 → 部件裁在它上面 → 蒙同一骨架 → 烘 morph → 层序 → 混搭预览 | 基础链路 |
| **P2** | **`orc`**（**同 profile、不同 rest/系数**） | ⭐ **「种族是一等公民」这一层** —— 若这层不成立，P3 会白做 |
| **P3** | **`centaur`**（**不同 skeleton_profile**） | ⭐ **「骨架契约可以多份」这一层** —— 会逼出"部位表不能硬编码 Legs" |
| 之后 | `child`（同 profile 的第二族）、`elf`/`demon`/… | — |

> **不要一上来做 10 个族**：抽象没验证就铺开，改一次要动 10 个族。
> 也**不要**第一个就上 `centaur`（同时验两个新抽象，分不清是哪个坏了）。

## 4. 交付件结构（目标形态）

```
assets/3d/rig/
  races/
    <race>/
      race.json                 ← 该族权威定义：skeleton_profile 引用 / rest / 身高范围 /
                                   shape_bones / 体形系数 / 几何安全包络 / layer×region 表 / 件清单
      body/body.blend           ← ★ 权威身体：完整皮肤 + 权重覆盖全部体形骨 + 承载骨架
      heads/*.blend             ← 可换头（纯刚体，挂 Head；不含脖子）
      parts/{layer}_{region}_*.blend   ← 每件独立资产，带 layer/region 标签
    humanoid/  orc/  centaur/  …
  profiles/
    humanoid_biped_65.json      ← 骨名 + 层级 + 顺序（rest 由各族提供）
    centaur_quad.json  …
  skeleton_mapping.json         ← ✅ 已落：65 骨 → VRM 角色词表
  channels.json                 ← 全局 morph 通道契约（BS_Thin=0 / BS_Heavy=1）
  SPEC.md / SKELETON.md / GENERATION-GUIDE.md
```

**运行时**：身体**永远加载**（它同时是**骨架的载体**），部件按需加载并重绑到身体的 `Skeleton3D`；
显示 = 一个 `visible` 开关；挂点用 **`BoneAttachment3D`**；头发/裙摆用 **`SpringBoneSimulator3D`**。
→ **`tools/3d/godot/shape-lab/` 的「逐件显隐 + 逐件读数」已经是这套的查看器雏形**。

## 5. 验收判据

**沿用 007/008（与网格来源无关，一套吃所有族）**：
38 项 bodyshape 断言（含"按 spec 重摆骨 == 已烘 morph"）｜`morph_digest` 逐位对账｜
臂展双信号（≈0 ⇒ 漏 along；≥±50% ⇒ 漏 `NONE`）｜零 morph 必败｜不是 `PASS` 而是**证明过会变红**｜
像素法穿模（**必须带双向标定**）｜偏斜守卫（读前记指纹、写前再校验）｜`run_check.py` 103/103。

**modular 专属新增**：
1. **接缝区权重一致性** —— 相邻模块在接缝附近**权重差异超阈值即报错**（否则抬臂会**撕开**）
2. **跨件穿模**（同层 / 跨层）—— 在**最瘦与最壮两档**下都验
3. **层序完备性** —— 每件必须声明合法 `layer` 与 `region`
4. **同族约束** —— 跨族拼接**在校验阶段被拒绝**（资产 ID 首段即 race，可直接字符串比对）
5. **孤儿骨** —— 每根骨要么映射到 VRM 角色、要么显式登记为额外骨（`tools/3d/skeleton/make_mapping.py` 已实现）

## 7. 不做

- ❌ 不重命名骨架（D5，破坏性）
- ❌ 不把现有 4 套收编（D10，= A 路线）
- ❌ 不用骨缩放做体型（与 `inherit_scale` 生命周期冲突；且 VRM 禁零/负缩放）
- ❌ 不在资产里带 IK 骨（Godot 有原生 IK，运行时加 `IKModifier3D`/`TwoBoneIK3D` 即可）
- ❌ 不用"重新生成一具更胖/更瘦的网格"来做体型（破坏 morph 前提）
