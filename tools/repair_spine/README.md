# repair_spine —— Spine 图集资源体检 / 修复工具

纯本地、确定性，**不联网、不消耗任何 AI 额度**。依赖 `numpy pillow scipy`。

> 面向 `xxx.json` + `xxx.atlas` + `xxx.png` 三件套（Spine 4.x），
> 以及「图集打包坏了 / 单图对不上 / 编辑器导入显示不对」这类问题。

## 主流程：一条命令

```bash
python pipelines.py build <原始.zip | 已解开的目录> -o assets/类目/性别/<项目>
#   一条命令走完：解压 → 页名/页尺寸修复 → 打包倍率还原 → 解包去污染
#                → 转目标版本(默认 4.3.26) → 交付顶层三件套 → 出预览图与交付说明
#   用户只需要确认最后那份 <目标版本> 三件套 + 复原预览图.png
```

产出：`<项目>.json/.atlas/.png`（**已是目标版本**）、`images_original/`、
`复原预览图*.png`、`交付说明.md`、`原始资源_<项目>.zip`（源三件套，随时可回退）。

### 多皮肤素材

**一套皮肤一张预览图**（Spine 的 `default` 是基底，命名皮肤是**叠加**在它上面，
所以每张渲染的是「default + 该皮肤」）：

* 单皮肤 → `复原预览图.png`（向后兼容）
* 多皮肤 → `复原预览图_<皮肤名>.png`
* ⚠️ **不能只拿 `default` 的预览验收** —— `default` 可能是不完整的（实测
  `RogueSekaniFlamebringer` 的 default 就不含腰部那套衣服），命名皮肤才是个别变体。

**为什么倍率修复放在"解包"这一步**（而不是转换前）：

1. 它属于**解包的完成度** —— 解包的定义就是把图集还原成每个附件自己的图；
   图出来了但尺寸不是 JSON 声明的尺寸，这活没干完，而且 `images_original/` 是要留下的交付物。
2. **预览图看不出差别** —— 渲染器按 JSON 声明的尺寸画四边形，纹理放大与否几何完全相同，
   所以往后放不会让预览更准。
3. **必须早于 Spine 导入**，而 `convert` 是刻意只吃「JSON + 单图」、不碰 atlas 的；
   塞进去会破坏这个分层。

### 需要分步排查时

上面每一步都能单独跑（同一条流水线的三段，互不覆盖）：

```bash
python pipelines.py prepare <zip|目录> -o <项目目录>   # 只解压+解包+出预览（--check 打体检）
python pipelines.py convert <项目目录>                 # 只转版本，产出 convert/
python pipelines.py apply   <项目目录>                 # 只做顶层替换 + 出交付说明
```

**硬性纪律**：`prepare` / `convert` 只写**新增**文件，**绝不覆盖**已交付的顶层三件套；
替换只发生在显式调用 `apply`（或一条龙的 `build`）时。加 `--backup` 才会把被替换的旧三件套
另存为 `_replaced_*`。`apply` 前提是原始版本已在 `原始资源_*.zip` 里。

### 版本转换走官方链路（不要手写格式转换器）

**Spine 4.x 拒绝直读 3.8 的导出数据**（`The Spine version must be the same version that exported
the data file`），必须两步：

```bat
:: A. 用**匹配版本**把 JSON 导入成 .spine 工程
Spine.com -u 3.8.99  -i cha_1114.json -o cha_1114.spine -r
:: B. 用**目标版本**打开工程（自动升级）导出 JSON + 重打包图集
Spine.com -u 4.3.26  -i cha_1114.spine -o <输出目录> -e json+pack
```

`convert` 子命令已把这条链路封装好：自动找 `Spine.com`、读
`%USERPROFILE%\Spine\updates\` 里**本地已下载**的版本（无需联网）、选匹配的源版本、跑完两步并做校验。
投影工程名决定导出名，所以工程要命名成 `<骨架名>.spine`。

## 快速开始（单项命令）

```bash
cd D:\artstudio\tools\repair_spine

# 1) 体检：页名、三方对账、尺寸倍率、矩形重叠、分区性
python pipelines.py diagnose  <目录>

# 1b) 规范化页名后缀 / 修复页图尺寸不符（**就地改**，prepare 会自动跑）
python pipelines.py pagefix   <目录>

# 2) 去污染：把邻居混进来的像素摘掉，导出未裁白原尺寸单图
python pipelines.py unpack    <目录> -o <目录>\images_original

# 3) 重打包：用干净单图生成**无重叠**的 atlas（骨架 JSON 不用改）
python pipelines.py repack    <目录> --from <目录>\images_original -o <目录>\repacked

# 4) 独立渲染 setup pose，拿它当验收基准图
python pipelines.py render    <目录> --images <目录>\images_original -o preview.png
#    加 --bones 会把骨骼叠到预览图上（排查"某部件为什么没显示"时很好用）
#    加 --skin <名> 指定皮肤；默认挑**部件最多**的那套（多皮肤资源的 default 常是空壳）

# 5) 反解回环 + 渲染包围盒校验
python pipelines.py verify    <目录> --images <目录>\images_original

# 6) 判断「该用哪一套图」：网格三角形投影回图像空间求 IoU
python pipelines.py meshfit   <目录> --images <目录>\images_original
```

`<目录>` = 包含 `json` / `atlas` / `png` 的文件夹（`diagnose/unpack/repack/render/verify` 会自动挑第一个）。

## 文件

| 文件 | 职责 |
|---|---|
| `pipelines.py` | **唯一工具**（由原 5 个模块合并）。流程命令：`build`（一条命令走完 prepare→convert→apply）/ `prepare` / `convert` / `apply` / `file`；排查命令：`diagnose` `pagefix` `unpack` `repack` `render` `verify` `meshfit` |

## 各命令在验什么

| 命令 | 判定依据 | 说明 |
|---|---|---|
| `diagnose` | **分区性**：各区域矩形内不透明像素之和 == 页图不透明像素总数 | 这是判断「图集打包是否合法」最快最硬的指标；超了就是矩形重叠 |
| `diagnose` | **附件声明尺寸 vs 图集 `orig`** | 抓「图集被打包成别的倍率」——**3.8 看着正常、转 4.x 必散架**（见下） |
| `diagnose` | 三方对账 JSON 引用 / atlas 区域 / 磁盘文件 | 名字层面缺谁补谁 |
| `diagnose` | 声明尺寸 vs 磁盘图片尺寸；网格 `width/height` vs atlas `ow,oh` | 抓「图集被降采样打包」 |
| `unpack` | 连通域归属（像素级 IoU 最大） | 外来像素与本体像素分属不同连通域 ⇒ **不会误删本体** |
| `repack` | 反解回环 + 新页重叠像素=0 | 重打包后 atlas 与单图必须能互相还原 |
| `render` | 渲染包围盒 == `skeleton.width/height` | 位置数据自洽性；对不上说明 JSON 几何有问题 |
| `meshfit` | 网格三角形投影回图像空间 vs 实际画面的 IoU；仿射 `sqrt\|det\|` | 判断该用哪套图；`sqrt\|det\|` 应≈骨骼 scale |

## 已实测确认的格式约定（踩过的坑）

1. **y 从页图「上边缘」向下量**（不是下边缘）。穷举 8 种约定后：`互换 + y 自上而下`
   越界 0、与真实连通域平均 IoU 0.915，其余组合明显更差。
2. **旋转区域的页内占位矩形宽高互换**（deg 90/270）。存进去是逆时针 90°，还原要顺时针 90°。
3. **`offsets` 的 `oy` 从下边缘量**；贴回原画布锚点 = `(ox, oh - oy - packedH)`。
4. **空行 = 换页**。写出 atlas 时，页属性之后**不能有空行**，否则官方解析器会把第一个区域名当成新页名。
   区域之间也不要空行。
5. **region 附件的 `(x, y)` 是区域中心**（不是左下角）。穷举 center/bl/br/tl/tr 五种锚点，
   用编辑器截图当基准比对，center 明显最优。
6. **加权网格** `vertices` 格式 = `骨数, [骨索引, x, y, 权重] × 骨数, ...`，
   骨骼索引是**全局骨骼序号**（不是 skin 的 `bones` 名字数组）；`len(vertices) != len(uvs)` 即为加权。
7. **网格 `regionUVs` 归一化在「未裁白原尺寸」上**，(0,0) = 左上。
8. **图片格式坑**：调色板 PNG（mode `P`）+ 逐索引 `tRNS`（例如 `transparency` = 0..77 共 78 项）
   在部分编辑器/引擎里会解析失败，表现为**白色占位块**。统一转成 RGBA 再交付。
9. **合成语义坑（自己写渲染器最容易翻车）**：画每个附件时**必须整层做 alpha 合成（over）**。
   如果按三角形用 `paste(tex, mask=三角形)` —— 那是**替换**语义，附件会在自己的**透明像素**处
   把下层已经画好的部件**擦掉**。症状非常有欺骗性：看起来像"某些部件没被读取/位置没显示"
   （例如斗笠的 231×90 四边形一盖，下面的脸和头发整块消失），而几何位置其实全对。
   正确姿势：把一个附件的所有三角形先画进独立的一层，再 `canvas.alpha_composite(layer)`。
10. **Spine 3.8 vs 4.x 的字段差异**：
    * 骨骼用 `transform`（3.8）/ `inherit`（4.x），取值字符串相同；
    * atlas 用旧式键名 `rotate/xy/size/orig/offset/index`（带缩进、文件开头可能有空行）；
    * 加权网格 `vertices` 格式两版一致（`骨数, [骨索引,x,y,权重]*`）。
    解析器/渲染器两个键名都要认，否则会静默走错分支。
11. **页名后缀可能与实际文件不符**（`Xxx.webp` vs 磁盘上的 `Xxx.png`）。
    `resolve_page_image()` 会依次试同名 → 换常见后缀 → 大小写不敏感匹配。
    ⚠️ 读不到页图时**必须报错**，不能 `continue` —— 否则体检把"没测"伪装成"通过"。
12. **页图可能被非等比重采样过。** 判据是「不透明像素落在区域矩形内的比例」：
    把图缩回 atlas 声明的尺寸后覆盖率显著更高（Nomad：93.26% → 99.90%），
    且缩回后精灵像素尺寸与 atlas 的 `size:` 逐字段吻合 ⇒ atlas 是基准。
    `pagefix` 会在两种假设（①缩图 ②size 行过期）间用这个指标二选一，都说不通就报错。
13. **别名区域**：`xy/size/orig/offset/rotate` 完全相同的区域是**同一张图的两个名字**
    （多皮肤共用），必须共享像素。按 `region_groups()` 分组后，
    覆盖计数与连通域归属都**按组**进行。
    ⚠️ **`diagnose` 的重叠检测也必须按组** —— 否则 `l_foot_4` / `l_foot_4 _a`（cha_1166）、
    `weapon` / `weapon_09`（cha_4205）会被误报成"1 对重叠、`分区=False`"，
    而那其实是 Spine 合法的"两个名字共用一个矩形"。
14. **零间距打包（矩形不重叠）时去污染必须是恒等变换。**
    像素只被一个组覆盖 → 无条件保留；只有**重叠区**才靠连通域 IoU 裁决。
    否则连通域横跨多矩形时会把本矩形的合法内容整块清空（实测误删 40%）。
    另有兜底：私有区占比 < 1% 且仲裁拿走一半以上 → 回退原始裁切，不交付空白图。
15. **图片名的解析顺序是 `path` > `name` > 附件键名。**
    只看 `path` 会漏掉所有只写 `name` 的附件（表现为图上只剩两只脚）。
    对账要**遍历所有皮肤**，并跳过 `boundingbox`/`path`/`point`/`clipping`（它们不带图片）。
16. **预览渲染要解 IK**（Spine 的 setup pose 本身就解，照抄官方 `IkConstraint.apply`），
    并挑选**部件最多**的皮肤（`default` 可能是空壳）。
    但若解了 IK 仍看着"散"，先加 `--bones` 确认每件是否落在自己的骨骼链末端 ——
    落在末端就是几何自洽，是素材 setup pose 本来的样子。
17. **「图集被打包成别的倍率」是步骤 1 必须报出来的缺陷** —— 它最会伪装：
    Spine 3.8 按 JSON 声明的 `width/height` 画四边形、纹理拉伸填充，所以**声明全尺寸 +
    图集 0.5 倍**时，3.8 渲染出来**只是糊、几何全对**，预览看着毫无问题；
    一旦转到 4.x，导出会**用图集尺寸重写附件尺寸**，精灵各自缩水、彼此错位。
    实测 NPC2：15/19 个附件是 0.5 倍 → 转成 4.3.26 后头变大、四肢脱落。

    判据（`size_scale_report` / `diagnose`）：逐个比对附件的 `width/height` 与图集对应区域的
    `orig`（`ow/oh`）。各附件倍率会有**取整抖动**（91/77=1.1818 vs 93/79=1.1772），
    所以要再搜一个最优缩放因子 `s`，看 `round(声明 * s) == 图集` 能解释多少项；
    全部能解释才算"一次干净的等比缩放"，给出的 `s` 就是放大还原要用的倍率
    （NPC2/qiaofeng = 0.500，Kimchul = 0.847）。
    ⚠️ 这条**不能只查 `mesh` 类型**：NPC2/qiaofeng 的附件是 `region`，会整个漏掉。
18. **同一个图集里可能有不同的打包倍率。** 实测 `RogueSekaniFlamebringer` 的 19 个附件里
    15 个是 0.5×、4 个本来就 1:1。所以还原必须**逐图**按 `declared / orig` 对齐到声明画布，
    **不能整页放大**（会把那 4 个弄坏，还会让它们的打包矩形变成未裁白画布的两倍）。
    改 JSON 也不行 —— 改了就轮到那 4 个错。
19. **渲染逐像素比对有三个坑**（不修就一直给出假数字）：
    * 4.x 移除了 `skeleton.x/y`，整只骨架平移（实测 595px）→ 比对时把源骨架的 x/y
      补到目标渲染上（`Renderer(sk_offset=...)`）；
    * 不能 `resize` 到较小尺寸再比 —— 包围盒尺寸一变就是整体拉伸，
      同一只角色只因包围盒差 1.9%，指标就从 12 px 跳到 28 万 px；要**按世界坐标对齐**
      （图像 pixel(0,0) ↔ 世界 `(bb[0], bb[3])`，把世界原点放到画布固定位置）；
    * **多皮肤要每套都比**，只比一套会漏掉皮肤专属部件。
20. **大角色的预览会撑爆画布**：1263×1835 的角色按 `ss=3` 是 3909×5625 = 2200 万像素，
   再 ×2 就是 7600×11000，每套皮肤一张 —— 直接超时。两道闸：
    `Renderer(max_px=4_000_000)` 自动降 `ss`；`render_previews(max_long=2600)` 限输出长边。
21. **Spine 升级会重算部分网格顶点**（伴随 `Reset invalid edges`），会让局部形状变化
    （实测 8 个火焰网格的 `vertices` 长度都变了，包围盒宽度 +1.93%）。这是官方行为，
    不是流程缺陷 —— 但要用**差异图**（红=只有源有 / 绿=只有目标有 / 蓝=两者都有）
    确认影响面，别只看一个数字。
22. **抠图判据：优先用「网格几何」，连通域只当兜底。**
    重叠区该归谁，最可靠的不是连通域，而是 **JSON 里网格的三角形** ——
    把 `uvs × (ow, oh)` 在画布空间光栅化，就得到"这个附件真正会采样画布的哪一块"
    （`mesh_coverage()`）。实测某素材**整页 1200×865 就是一个连通域**（面积 428103），
    连通域归属彻底失效，把区域自己的像素当外来像素删了，`footL` 的鞋被切掉 47%。

    优先级：**网格几何 > 别名组 > 连通域仲裁（兜底）**。实现要点：

    * `linkedmesh` 没有顶点，要顺 `parent`/`skin` 找到真正带网格的那个（最多 8 层）；
    * 同一张图可能被多个附件引用，掩码取**并集**；
    * `region` 类型没有网格 -> 返回 `None`，退回连通域判据；
    * 掩码**外扩 2px**，否则削掉抗锯齿边；
    * 画布空间 -> 页内矩形空间要做**旋转的反变换**（`crop_trimmed` 用 `ROTATE_270`，
      反变换是 `ROTATE_90`）。

    回归依据：用新判据重跑**已交付的 cha_1114**，与已交付 `images_original/`
    **只差 23 像素 / 3 个区域**（旧判据当时差 22 像素）—— 旧素材不改变、新素材修好。
23. **抠图前先出一张「透明图层描边 + 序号」的图**（`ndimage.label` + 边缘描边 + 质心标号），
    这是发现"整页只有一个连通域"这类结构问题的现成手段。
    另外 `region` 类型附件的 `bounds` 是**未裁白**尺寸（`orig == size`、`offset 0,0`），
    矩形本来就比精灵大，**带空白是正常的**，不等于抠错了。
24. **收紧区域（`tight_pack`）能做的很有限 —— 先说清楚它做不到什么。**
    它按同一套规则把每个区域裁到"实际用到的范围"（有网格用网格 bbox、无网格用内容 bbox、
    外扩 2px），重写 atlas 的 `offsets` 并重打包。实测某素材 **55 个区域只有 10 个真的变小
    （省 1%）**，因为源素材是**未裁白**的（`orig == size`、`offset 0,0`），
    **画布本来就是内容的紧包围盒**，没有空白可裁。

    ⚠️ **"让区域框贴合美术"在 atlas 层面做不到**：图集区域永远是**轴对齐矩形**，
    而精灵常常是斜的/细长的（实测有的部件只填了 19.5%、33%、55%），
    **斜着的大腿其轴对齐包围盒天生就比它大一圈**。网格（编辑器里的青色轮廓）才是贴合的形状。
    动手前先用"画布 vs 内容 bbox vs 网格 bbox"三个数确认到底有没有可裁的。

    实现要点：atlas 写 `pma:true` 就必须交**预乘**像素（我们的单图是直通 alpha，
    不分青红皂白打包会让半透明边缘发暗）；`tight_pack` 的 `pad_px`
    **必须 >= `decontaminate` 的 `mesh_pad`**，否则会削掉那一圈外扩边。

## 验收纪律

* `unpack` 去污染后，**必须**用 `meshfit` 或渲染前后对比确认「没有把本体删掉」——
  连通域归属天然不会删本体，但归属本身可能判错，要用客观指标复核。
* `repack` 后**必须**跑 `verify`：反解回环要一致，新页重叠像素要为 0。
* 结论不要靠肉眼。用包围盒、IoU、分区性这些**可复算**的量来判。
* **经 Spine 重打包的图集**，回环校验会有几个像素差（Spine 按 alpha 阈值削掉最外圈
  alpha 1~3 的边）。这是"裁剪舍入"不是"真错"：RGB 在**预乘域**比（容差 1），
  alpha 给 `alpha_tol`（默认 0；重打包产物用 4）。
* **删除纪律**：`apply` 只替换顶层三件套，且前提是原始版本已在 `原始资源_*.zip` 里。
  用户没明确说要删的衍生文件（例如 `_fullsize.json`）**默认保留**，主动问一句再动。
