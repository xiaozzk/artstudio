## 5. 对称性检查

以画布中心 x = 192.5 为轴，各部件中心的水平偏移：

| 部件 | 中心 x | 偏移 | 左右配对偏差 |
|------|--------|------|--------------|
| `head` | 181.5 | **-11.0** | — （头部整体偏左 11 px） |
| `torso` | 191.0 | -1.5 | — （基本居中） |
| `right_arm` / `left_arm` | 72.5 / 310.5 | -120.0 / +118.0 | 2.0 px |
| `right_arm_wrist` / `left_arm_wrist` | 37.0 / 350.0 | -155.5 / +157.5 | 2.0 px |
| `right_leg` / `left_leg` | 109.0 / 269.0 | -83.5 / +76.5 | **7.0 px** |
| `right_leg_foot` / `left_leg_foot` | 105.0 / 299.5 | -87.5 / +107.0 | **19.5 px** |

**需要留意的三处：**

1. `head` 整体偏左 11 px（约 2.3% 头宽）—— 属于轻微不对称，可能是头部姿态（微侧）而非错误。
2. `left_leg_foot` 比 `right_leg_foot` **宽 17 px 且低 11 px**（1671 vs 1660，左脚本应落在同一地线），左右脚形态不一致。
3. 无「膝 / 肘」独立部件：`*_leg` 是一整条腿（615 px），`*_arm` 是一整条大臂（526 px）。**当前部件拆分没有提供肘、膝两个关节的切分点**。

## 6. 对 Spine / Godot 落地的直接影响

- **地线 / pivot 基准**：角色最低点 y = 1671，水平中心 x = 192.5。Spine 中建议把 `root` 骨骼放在 **`(192.5, 1671)`**（脚底中心），这样骨架原点即角色站立接触点。
- **关节位置可直接推导**（无需猜）：
  - 颈 / 头骨 → 取 `head` 底边中点附近 `(181.5, 484)`
  - 肩 → 肩线 y = 442 与左右臂中心 x 的交点：约 `(72.5, 442)` / `(310.5, 442)`
  - 腕 → y = 968/962 与手腕中心 x：约 `(37, 968)` / `(350, 962)`
  - 胯 → 腿根 y = 922 与腿中心 x：约 `(109, 922)` / `(269, 922)`
  - 踝 → y = 1509：约 `(105, 1509)` / `(299.5, 1509)`
  - ⚠️ 肘、膝**无实测分界**，需人工指定或先在 PS 中把 `*_arm` / `*_leg` 拆成两段。
- **缩放建议**：按 100 px = 1 Spine unit 导入，角色总高 = **16.70 unit**；按 1670 px = 1 unit 则该角色为 1 unit 高（Godot 中 ≈ 1 格）。选定后在项目内统一，不要逐次改。
- **导入方式**：各图层按画布坐标整幅导出（385 × 1672，保留透明区），pivot 用画布坐标记录，可保证所有部件在 Spine 中自动对齐，无需手工对位。

## 7. 数据文件说明

本表数据由一次性 ExtendScript 读取 `Layer.bounds` 生成，字段含义：

- `bounds` = `[左, 上, 右, 下]`，单位为文档像素，尺寸 = 右下 - 左上
- `高 / H` = 部件包围盒高度 ÷ 角色总高 1670 px
- 所有宽高均为**包围盒**尺寸，非实际不透明像素轮廓的精确外接形状（对斜置的手臂等部件会略大于视觉宽度）
