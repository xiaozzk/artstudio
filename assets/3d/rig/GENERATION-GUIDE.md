# 素材生成指南 + morph 经验总结（面向自研 / Tripo 生成）

> **读者**：以后自己生成素材的人（含 AI 生成）。
> **目的**：让**服装 × 体型**的灵活性最大化，并且**一次做对**，不用回头补"剥离 / 贴合 / 传递"。
> **依据**：`SPEC.md` 的 35 条实测事实 + `task/007-morph-pipeline/` 的独立验收结论。
> **配套**：契约 [`SPEC.md`](SPEC.md)｜pipeline [`README.md`](README.md)｜复杂度报告 [`../../../task/007-morph-pipeline/verify/COMPLEXITY.md`](../../../task/007-morph-pipeline/verify/COMPLEXITY.md)

---

## 0. 一句话

> **只生成一具"基准体"，让所有服装都在它身上裁、都蒙同一副骨架；
> 体型变化靠"摆骨 → 烘 morph"派生，绝不靠"再生成一具不同体型的身体"。**

这一条同时解决三件事：**服装跟得上体型**、**不穿模**、**资产量不爆炸**。

# 第一部分：morph 经验总结（15 条，都是踩出来的）

## 1.1 原理层（先懂这 4 条，后面全是推论）

| # | 事实 | 推论 |
|---|---|---|
| 1 | **morph（blend shape）= 逐顶点 float3 偏移表**，每档占 `顶点数 × 12 字节` | 数据量对"每件网格"线性，与档数线性。**实测：4 个自包含角色 / 40 件 / 2 档 ≈ 1,976 KB**，不是瓶颈 |
| 2 | **同一 mesh 的各档必须有完全相同的顶点数与面序** | **这是 morph 的硬前提** → **形状变化不能靠"重新生成一具网格"**，只能靠形变（骨缩放）→ 烘成偏移表 |
| 3 | 身体与每件服装各持**同名同序**的 morph，运行时由**一个数值**同步驱动 | 名称与索引都是**硬契约**（我们的口径：`BS_Thin`=**0** / `BS_Heavy`=**1**，Blender key_block 1/2） |
| 4 | **身高必须与体型正交** —— 身高走**角色根节点等比缩放**，**不做 morph、也不缩 `root` 骨** | 缩 `root` 骨与 `inherit_scale='NONE'` 冲突：实测身高只 **+0.50%**、拉伸离散度 **0.0841**（超阈值 8.4×）；对象级是 **+8.00% / 0.00003** |

## 1.2 路线层（最重要的一条洞察）

**不要引入"一具独立的标准体"再让服装去贴合它。** 我们为此绕了一大圈：

| 路线 | 做法 | 工序 | 人工介入 | 裸露身体（像素法） | 评级 |
|---|---|---|---|---|---|
| A | 独立标准体 + 剥离/贴合/外推 | 3 | 4 个几何贴合类 | **74% → 44%** ❌ | **高** |
| B1 | 换**同源**身体 + 跨网格传递 | 3 | 1 个 | 无 | **中** |
| **B2** ⭐ | morph **派生在角色自身网格**上 | **1** | **0 个** | **结构性为 0** | **低** |

**为什么 B2 低**：如果最终角色**本身就是完整的**（自带 rig + 布料 + 皮肤 + 头），那么"身体与服装体型基准不一致"**这个问题不存在** → 也就**不需要**剥离、贴合、传递。
**门槛不在"morph 怎么传"，而在"服装网格是按哪具身体裁的"** —— 这是一个**美术/资产决策**，决策错了，后面所有自动化只能补偿、不能修复。

## 1.3 实操层（尺寸 / 口径）

| 项 | 我们的取值（可作起点） | 备注 |
|---|---|---|
| 档位系数 | **thin 0.84 / heavy 1.21** | 围度变化见下 |
| 骨缩放口径 | **`girth`**：`scale = (s, 1, s)` —— 只缩垂直于骨轴的两轴，**骨长不变** | 含骨长的口径会让身高跟着变（±11%） |
| 沿骨轴项 | **只对"骨轴水平"的骨开**（锁骨 head/tail 的 z 精确相同）→ 改肩宽而**身高代价 0** | 其他骨轴竖直，开它等于改身高 → 必须保持 0 |
| 体形骨 | **14 根**（`pelvis` / `spine_01..03` / `thigh_l,r` / `calf_l,r` / `upperarm_l,r` / `lowerarm_l,r` / `clavicle_l,r`） | 头/眼/眉**不参与**（它们是 `static_by_design`） |
| 几何安全包络 | 翻转面 0 个：**0.58 ≤ coef ≤ 1.45（女）/ ≤1.25（男）**；0.58 时左右腿间隙仍 **+0.63 cm** | 这是**几何上限**，不是推荐范围 |
| 效果实测 | 围度 瘦 **−14~−17%** / 壮 **+19~+27%**；臂展 **±1.7~2.6%**；剪影 XOR **女 33.6% / 男 30.7%**（≈等效身高 5.55% / 4.94%，即身高滑块可用区间的 62–69%） | 双尺子：关键围度 + 剪影 XOR |

## 1.4 坑层（这一节最值钱）

| # | 坑 | 症状 | 规则 |
|---|---|---|---|
| 1 | **shape key 不改 `mesh.vertices`** | 读 `mesh.vertices` 会以为"没变化" | 一律走 **depsgraph 求值** |
| 2 | **写完 shape key data 后求值缓存失效** | 身高对、Thin 对、**只有 Heavy 掉到 0.03 cm** | 每次改 key data 后**重新 `depsgraph_get()` / `view_layer.update()`** 再取值 |
| 3 | **`pose` 与 `shape key` 是两套独立形变来源、会叠加** | 量形时读到 **33 mm 假差** | 量之前**同时**清 pose 与 shape key 权重 |
| 4 | **`inherit_scale='NONE'` 有"生命周期"之分** | 拿"资产里是不是 NONE"当判据 → 误判 | **烘焙期**（摆骨用的那具体）**必须 NONE**；**交付期**运行时资产**应还原 FULL** |
| 5 | **`inherit_scale` 只断"缩放"继承、不断"位置"继承** | 缩 `pelvis` 会让**脚也动 15.9 mm** | 它是**烘焙期工具**，不是姿态隔离 |
| 6 | **骨索引不可硬编码** | 同一骨架在 Blender 里 `Head=6`、在 Godot 里 `Head=54` | **索引取决于「该文件里的骨层级 DFS 顺序」、跨文件不可复用** → 一律 `find_bone("Head")` |
| 7 | **`blender -b --python X.py` 抛异常仍返回 exit 0** | 门禁全绿、产物却是旧版 | 加 **`--python-exit-code 1`** + 扫 `Traceback` + 产物 sha256 前后比对 |
| 8 | **"测出的零"可能是判据退化** | 布料↔皮肤"位移差 ≈ 1 个 float32 eps"曾被当铁证 —— 实则那批点在**手腕/手（刚体）**，位移差**必然为 0** | 测前先问：**在我选的这个点集上，这个量「可能不为零」吗？** |
| 9 | **合成壳不能用顶点法线外推** | 凹处把点推进邻肢 | 标准体相对质心**非星形**（仅 67.2% 面满足）→ 要造壳得用别的办法 |
| 10 | **像素法必须带双向标定** | 不带标定在"无身体"图上**误报 37.3%** | 只渲身体必须 **100.00%**、只渲服装必须 **0.00%**，不过就报错；材质须 Emission 纯色 + `view_transform='Standard'` |
| 11 | **指纹里混进"纯展示性版本号"** | 改文档 → 语义指纹变 → 下游守卫**误报** | **指纹只由"会影响结果的量"构成** |
| 12 | **"自洽 ≠ 正确"** | 28 项断言只证"文件↔manifest 自洽"，改系数不重烘**照样全绿** | 门禁必须**闭合到最终产物**（"按 spec 重摆骨"要与"已烘 morph"逐顶点一致） |
| 13 | **依赖顺序也是正确性** | 下游读到旧系数 → 身体 v2 / 服装 v1，**窗口只有 1 秒** | 下游**读前记指纹、写前再校验**，变了就报错退出 |
| 14 | **索引顺序是硬契约** | 重排档位 = 所有下游**静默变形** | **新档一律追加在末尾** |
| 15 | **"零拷贝"这类否定性声明会被自己的工具证伪** | 探针写了相对路径 → 图落进工程内部 | 交付前跑目录自查；**声明要用产物证明** |

# 第二部分：你应该怎么生成（保证服装 × 体型最大灵活性）

## 2.1 三条铁律

### 铁律 1 —— **只生成一具基准体，所有东西都从它派生**
**不要**分别独立生成"身体"和"服装"。独立生成 = 体形基准不一致 = 回到 A 路线那套人工成本。
> 若用 AI 生成：**先生成一具（可接受就冻结），再以它为参照去生成/裁剪每一件服装**；
> 若分两次生成，**两次的体型比例不会一致**，失配照样出现甚至更严重。

### 铁律 2 —— **一副骨架贯穿所有件，骨名与骨序完全一致**
- 骨架**只做一次**，之后所有资产都 skin 到它（骨序由文件内 DFS 顺序决定，**跨文件不可复用**，所以"复用同一副骨架"比"重新生成一副名字一样的"安全得多）
- 术语：**骨名集合 + 层级**必须一致；**不要**依赖索引
- 建议：**65 骨通用人形**（我们这套：`root/pelvis/spine_01..03/neck_01/Head/clavicle_*/upperarm_*/lowerarm_*/hand_*/thigh_*/calf_*/foot_*/ball_*`）
- ⚠ 小腿骨叫 **`calf_l/calf_r`**，**没有** `shin_*`

### 铁律 3 —— **体型变化靠"摆骨 → 烘 morph"，不靠"再生成一具身体"**
这是 morph 能成立的前提（各档顶点数/拓扑必须一致）。
**所以你的生成器只需要产出一具基准形状**；瘦/标准/壮是**派生**出来的。

## 2.2 推荐流程（照这个顺序做）

```
① 生成【唯一基准体】（裸模；带不带头都行）
        ↓
② 规范化：骨名/骨序/rest 固定 → 得到"标准体"
   · rest 用 T-pose；**不要摆任何 pose**
   · 体形骨的全部直接子骨设 inherit_scale='NONE'（烘焙期契约）
        ↓
③ 生成每一件服装：**在这具基准体上**裁/生成，并 skin 到同一副骨架
   · 关键：**不要给服装单独生成一具身体**（那是 A 路线的根源）
   · 布料与皮肤**分属不同材质**，别烤进同一材质
        ↓
④ 派生体型档位：按 spec 摆【体形骨】的 scale
   → depsgraph 求值 → 把形变**逐件烘成同名 shape key**
        ↓
⑤ 身高：另走【角色根节点等比缩放】（不做 morph）
        ↓
⑥ 烘完把 inherit_scale 还原 FULL（交付期契约），清 pose、清权重
```

**工位可复用**：本仓库已实现 ①~⑥（`tools/3d/make_standard_body.py` → `bodyshape/derive.py` → `garment/derive_on_character.py → build_all.py`），
换网格后**只需重调系数**（见 2.4）。

## 2.3 生成清单（逐条自检）

| 项 | 要求 | 为什么 |
|---|---|---|
| **骨架** | 65 骨、**骨名与骨序固定**；**导出一次，其余全部复用** | 骨序跨文件不可复用；换骨架 = 全部权重失效 |
| **rest pose** | **T-pose**，不要摆 pose | 摆过 pose 的 rest 会让 morph 基准错位 |
| **拓扑** | **每个 mesh 在所有档位下顶点数 + 面序完全一致** | morph 的硬前提 |
| **蒙皮** | 权重覆盖到"会形变的骨"；手/指这类**不属于体形骨**的部件无所谓（刚体） | 手是刚体 → 那里的相对几何不可能随体型恶化 |
| **材质** | **布料 / 皮肤 / 头 分成不同材质** | 混在同一材质里会逼出"剥离"这一步（我们被迫做过，现在不需要了） |
| **头** | **独立成件、挂 `Head` 骨** | 实测头/眼/眉**不随体型变**（`static_by_design`）→ **捏脸成本可与体型解耦** |
| **服装覆盖** | 若要 **B2**（推荐）：**别做"裸露躯干"**（泳装/裸露护甲） | 那种布料不包住躯干 → **体型变化没有载体** |
| **身体** | **只生成一具** | 多具身体 = 多套基准 = 回到 A 路线 |
| **UV / 贴图** | 贴图可内嵌（我们实测单角色 glb 42–53 MB 是贴图占大头） | 便于零拷贝加载；若要瘦身再走外部共享贴图 |

## 2.4 什么时候**必须**回到 B1

**只有一种情况**：需要**"裸露躯干"的服装**（泳装 / 裸露护甲）—— 那时布料盖不住躯干，
**体型变化没有载体**，B2 无解 → 必须用 B1（同源身体 + 跨网格传递）。

⚠ **走 B1 之前必须先写死"传递口径"**：我们实测两个独立实现在**远绑定顶点**上差 **1.11 cm**，
而**两者都符合字面描述**（SPEC **F20**）—— 这是当前唯一欠定义的环节。

> **好消息**：**同源之后 B1 与 B2 收敛为同一件事**。只要你做到"先生成唯一基准体、再以它为基准裁衣服"，
> 那具身体就同时是服装的基准，"身体与服装不一致"永远不出现。

## 2.5 换网格后要重做什么（迁移清单）

| 步骤 | 是否要重做 | 说明 |
|---|---|---|
| 骨架 / 契约 / 校验脚本 | ❌ 不变 | 与网格来源无关 |
| `morph_digest` / 拓扑 / 数据量校验 | ❌ 不变 | 直接可跑新资产 |
| **`delta_response` 的 9 个响应值** | ✅ **必须重调** | 它是**针对当前网格**调出来的，且目前**没有客观判据**（唯一的人时项） |
| 几何安全包络 | ✅ 要重测 | 翻转面/腿间隙随网格变 |
| 身高口径 | ❌ 不变 | 一律根节点等比缩放 |

**重调系数时的判据**（可直接复用我们的两把尺子）：
① **关键围度**（切片 → 2D 凸包周长 = 软尺量法，**对破洞/面绕向免疫**）→ 瘦/壮各变多少 %；
② **剪影 XOR** + 换算成**等效身高变化**（用"项目内已被认可看得出来"的对照物当标尺；
⚠ 标尺曲线是**凹的**，**必须分段插值**，从端点线性折算会高估 —— 我们踩过，把 5.45% 报成 6.82%）。

**验收判据（三条"能变红"的断言）**：
- **臂展 ≈ 0（±0.46%）⇒ 漏了沿骨轴项**；**臂展 ≥ ±50% ⇒ 漏了 `NONE` 隔离**（实测 −54.53% / +138.86%）
- **零 morph 必须被判失败**（"体形骨有权重"与"实测位移"必须**同向**）
- **按 spec 重摆骨 == 已烘 morph**（逐顶点比对，我们实测误差 **0.000000 mm**）

# 第三部分：`bodyshape` 应该用什么格式

## 3.1 核心原则：**只存"骨级缩放向量"，不存逐顶点数据**

| 该存 | 不该存 |
|---|---|
| **每根体形骨的 3 轴 scale**（几个数字） | ❌ 逐顶点偏移表（那已经是**产物**，不是**定义**） |
| 组的响应系数（`delta_response` / `along_axis_response`） | ❌ 绝对顶点坐标 |
| 通道名 + **索引**（硬契约） | ❌ "第 N 档应该长什么样"的图片/描述 |

**理由**：骨级向量可以**重定向到任何新网格**（换身体只重调系数）；逐顶点数据**绑死在某一具网格**上，换网格就必须全部重做。

## 3.2 推荐 schema（我们正在用的，可直接照搬）

```jsonc
{
  "schema": "bodyshape-spec",
  "version": "2.0",                    // ← 系数契约版本：只有动系数才变
  "coefficients_fingerprint": "ca93ef91…",  // ← 系数的语义指纹（见 3.4）
  "bones_field_revision": "2.1",       // ← 字段语义/文档修订，不进指纹

  "axis_profile": {
    "name": "girth",
    "rule": "x = z = 1 + (coef-1)*delta_response[group]；y = 1 + (coef-1)*along_axis_response[group]",
    "why": "含沿骨轴缩放会让身高跟着变 → 身高必须是独立正交的滑块"
  },

  "shape_bones": ["pelvis","spine_01","spine_02","spine_03",
                  "thigh_l","thigh_r","calf_l","calf_r",
                  "upperarm_l","upperarm_r","lowerarm_l","lowerarm_r",
                  "clavicle_l","clavicle_r"],          // ← 14 根，头/眼/眉不在内

  "groups": { "thigh": ["thigh_l","thigh_r"], "clavicle": ["clavicle_l","clavicle_r"], ... },

  "delta_response":       { "pelvis":1.0, "spine_02":1.0, "thigh":0.95, "calf":0.85,
                            "upperarm":1.05, "lowerarm":0.95, "clavicle":0.8 },
  "along_axis_response":  { "clavicle": 0.5 },          // ← 只给"骨轴水平"的骨开

  "morph_channels": [                                   // ← 名称 + 索引 = 硬契约
    {"name":"BS_Thin",  "morph_target_index":0, "key_block_index":1},
    {"name":"BS_Heavy", "morph_target_index":1, "key_block_index":2}
  ],

  "tiers": [                                            // ← 追加式；绝不重排
    { "name":"thin", "shape_key":"BS_Thin", "morph_target_index":0, "key_block_index":1,
      "target_coefficient": 0.84,
      "bones": { "pelvis":[0.84,1.0,0.84], "clavicle_l":[0.872,0.92,0.872], ... } },
    { "name":"heavy", "shape_key":"BS_Heavy", "morph_target_index":1, "key_block_index":2,
      "target_coefficient": 1.21,
      "bones": { "pelvis":[1.21,1.0,1.21], "clavicle_l":[1.168,1.105,1.168], ... } }

  "runtime": {
    "weight_range": [0,1], "default_weight": 0,
    "height": "角色根节点等比缩放 h∈[0.92,1.08]（不做 morph、不缩 root 骨）"

```

## 3.3 三条格式设计规则（都是踩出来的）

1. **`tiers[].bones` 必须只有一份权威，且必须是"实摆三轴"**
   我们曾同时存在"规范形 `(s,1,s)`"与"实摆三轴"两处，**不一致** → 下游照规范形读，**静默丢掉肩宽/臂展项**（其余数字全正常、不报错）。
   → 规范形若要留，**改名另存**（我们留成 `bones_canonical_girth`）并明示"**参考用、别拿来摆骨**"。
2. **追加式档位**：`BS_Stocky` → `morph_target_index 2` / `key_block_index 3`，**加在末尾**。
   glTF 的 morph target **按下标引用**，追加不动 0/1 的含义 → 既有服装**全部继续有效**；**重排 = 所有下游静默变形**。
3. **指纹只由"会影响结果的量"构成**
   我们踩过：改字段语义时顺手把 `spec.version` 升了号，**而 `spec_version` 是指纹的输入** → 指纹变化 → 下游守卫**误报"语义变化"**。
   → **纯展示性版本号不得进指纹**；字段语义修订另立一个**不进指纹**的键。

## 3.4 版本与对账：三重指纹，各司其职

| 键 | 用途 | 稳定性 |
|---|---|---|
| **`coefficients_fingerprint`** | **语义首选**：系数任一变它就变 | ★ 不受 mtime/文档改动误伤 |
| `spec_sha256` / `manifest_sha256` | **跨成员对账**（"我们读到的是不是同一份"） | 中等（改文档就变） |
| 文件 `sha256 + mtime + size` | **兜底硬失败** | 最灵敏（也最容易被误伤） |

**下游必须"读前记指纹、写前再校验，变了就报错退出"** —— 实测事故窗口只有 **1 秒**（下游 18:20:20 读、新版 18:20:21 落盘），却造成"身体 v2 / 服装 v1"的语义分裂。

**逐位对账用什么**：`morph_digest`（**比字节**，不是比统计量）——
约定必须写全：按 `object.name` 排序 → 全部件 → 逐顶点 → `key_blocks[K].data[i].co` **绝对坐标（非 Basis 偏移）** → `struct.pack("<3f")` → `sha256[:16]`，并给一个 `basis_digest` 作**负对照**。
（我们三方各自独立实现，8/8 逐位一致；而"绝对 vs 偏移"这个口径没写清时，**双方都算得出数字却对不上**。）

## 3.5 如果你用 AI 生成：它能给什么、必须你来补什么

| 环节 | AI 能直接给 | 必须你补 |
|---|---|---|
| 网格 | ✅ 基准形状 | — |
| 骨架 | ⚠️ 有时给，但**骨名/骨序不可控** | **规范化成固定 65 骨 + 固定骨序** |
| 蒙皮权重 | ⚠️ 质量不定 | 检查/重绑到你的骨架 |
| **morph / shape key** | ❌ **基本不会给** | **自己做"摆骨 → 烘 morph"**（本仓库的工具链） |
| 拓扑可控性 | ❌ **不同次生成拓扑不同** | **这是接入前的硬前提**：morph 要求各档顶点数一致 → 只能生成**一具**，形状变化靠派生 |
| 材质分组 | ⚠️ 常把皮肤/布料烤在一起 | **要求分开**（否则被迫做"剥离"） |
