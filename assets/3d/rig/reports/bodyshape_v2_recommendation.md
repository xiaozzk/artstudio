## 1. 判据（都可复算，不靠"看起来明显吗"）

| # | 判据 | 工具 | 为什么可信 |
|---|---|---|---|
| ① | **关键围度**（胸/腰/臀/上臂/大腿/小腿）三档间的变化 % | `measure_girth.py` | 切片 → 投影 → **2D 凸包周长**。凸包等价于软尺量法（跨过凹处），且对**破洞与面绕向免疫** —— 标准体有 26 个连通域 / 48 条边界环（SPEC F15），用"边界环求周长"必然错 |
| ② | **剪影 XOR 差异率** + 剪影面积 + 最大行宽 | `silhouette_metric.py` | 正交前视、`film_transparent`（剪影 = alpha，不用颜色阈值 —— F16 的教训） |
| ③ | 把 ② 换算成 **"等效身高变化"** | 同上 | 用**已被项目认可"看得出来"的对照物**：身高滑块（对象级等比缩放 1.00→1.08，SPEC §3.4）。不是我的主观刻度 |

> ⚠ **诚实边界**：身高变化是纵向铺开、围度变化是横向铺开，差异分布不同 →
> 「等效身高」是**可复现的量级标尺**，不是严格的心理物理等价。两个量都报。
>
> ⚠ **换算方法**：标尺曲线是**凹的**（差异率随身高增大而饱和），必须在实测的
> 1.00/1.02/1.04/1.06/1.08 五点内做**分段线性插值**。直接拿 8% 那点线性折算会系统性高估
> —— 我第一版就是这么写的，把 5.45% 报成了 6.82%。已修正。

### 2.4 v1 → v2 改了什么、为什么

| 改动 | 理由（都有实测支撑） |
|---|---|
| `spine_02` 0.92→1.0、`spine_03` 0.85→1.0 | v1 的**胸腔响应只有骨盆的 72%**（胸 −9.8% vs 臀 −13.6%）。衣服下胸腔比骨盆更显眼，这里被压住最亏 |
| `clavicle` 0.5→0.8 | 肩背厚度跟上 |
| **新增** `along_axis_response.clavicle = 0.5` | 锁骨的 head/tail **z 完全相同（精确水平）** → 沿骨轴缩放改的是**肩宽/臂展**，不是身高。实测身高比仍是 1.0002/0.9998。这是唯一能免费拿到轮廓宽度响应的杠杆 |
| 系数 0.86/1.16 → 0.84/1.21 | 在上述两项修好之后，再把整体推到位 |

**为什么不推更狠**：压到 0.72/1.35 实测几何仍健康（0 个翻转面、腿间隙仍为正），所以**限制不是几何，

剩下那点主观的"看起来弱"，实测指向**出图表现**：三档并排时手臂被画幅左右裁掉、且相邻两档手臂互相压住，

### 3.3 线性插值会不会出现"不像人"的中间态

**不会 —— 这是可证的，而且我实测验证了。**

**为什么**：体形档位之间**只差一组"每骨缩放"向量**。线性混合蒙皮（LBS）的顶点位置对
"每骨缩放"是**仿射线性**的（每根骨的矩阵里，线性部分只依赖自己的缩放、平移部分只依赖祖先的缩放，
**没有两根骨缩放相乘的交叉项**）。所以：

```
w·v(s_thin) + (1-w)·v(s_heavy) ≡ v(w·s_thin + (1-w)·s_heavy)
```

→ shape key 在任意权重下的线性混合，**恰好等于**把系数线性插值后重新摆骨的结果。
中间态永远是一个"合法的、只是系数不同的身材"，不存在插值伪影。

**实测证据**（`measure_girth.py --check-interp`）：

| w | 等价系数 | morph 线性混合 vs 等价 pose 的逐顶点最大差 |
|---|---|---|
| 0.00 | 0.840 | 0.000409 mm |
| 0.25 | 0.932 | 0.000478 mm |
| 0.50 | 1.025 | 0.000408 mm |
| 0.75 | 1.117 | 0.000492 mm |
| 1.00 | 1.210 | 0.000448 mm |

（女体；男体同级 0.00037–0.00061 mm）= **float32 舍入量级**。

**唯一会让中间态"不像人"的情形**：如果**将来**给不同部位**互相独立的系数**（比如腿瘦 + 躯干胖），
线性混合就可能在中间产生现实中不存在的组合。**目前单一系数驱动，不存在这个问题**；
要引入分部位控制时必须重新评估。

另外还有一条独立的护栏：极端档本身可以很极端，但**混合路径会经过中间系数** ——
例如新增 `BS_Stocky = 1.45`，则 `BS_Thin ↔ BS_Stocky` 的中间会经过 1.145，
依然落在安全包络内（3.1 的表）。

## 4. 索引顺序建议（明确建议）

> **追加在末尾。绝不要重排。**

```
现状：  key_blocks[0]=Basis   [1]=BS_Thin  [2]=BS_Heavy     glTF targets: 0=BS_Thin 1=BS_Heavy
加档：  key_blocks[0]=Basis   [1]=BS_Thin  [2]=BS_Heavy  [3]=BS_Stocky
                             glTF targets: 0=BS_Thin 1=BS_Heavy 2=BS_Stocky
```

理由：

1. **glTF 的 morph target 是按下标引用的**。追加不改变 0/1 的含义 → 已导出的服装 / 角色
   morph 全部继续有效；重排会让每一个已有 target 的含义错位，等于所有下游产物**静默变形**
   （不报错，只是 `BS_Heavy` 变成了别的东西 —— 和 D-1 那次版本偏斜同一类事故）。
2. **Blender 侧 `Basis` 永远是 `key_blocks[0]`**，`BS_*` 从 1 开始。而 **glTF 不导出 Basis**，
   所以 glTF 的 target 0 = `BS_Thin`。这两套索引**必须同时记在 manifest 里**
   （`morph_target_index` 与 `key_block_index`），下游各取所需。
3. 追加之后，**新档与旧档的语义是"同一根轴上的更远一格"**，运行时一个权重值 still 驱动全部；
   重排则会让"权重含义"本身变化，语义上也是更重的改动。
4. 代价对称：追加时"多一档"只是多一个 target；重排时"多一档"= 全量重烘 + 重导出 + 重测。

## 6. `--retune thin=0.80,heavy=1.25` 的注意事项

`--retune` 会**同时**改变系数并**重写两份 spec**（`--write-spec`）。改了就必须让
`garment` / `godot-preview` / `verifier` 知道 —— 他们的 morph 与之上的所有数字都绑在同一组系数上。

**判定版本请只认 manifest 里的这四行**：`spec_version` / `coefficients` /
`delta_response_values` + `along_axis_response_values` / **`coefficients_fingerprint`**。
`coefficients_fingerprint` 是这组系数的语义指纹，**系数一变它必变**，比 mtime 稳、比文件 sha 准。

> 这次 D-1 版本偏斜的教训：`garment` 18:20:20 读到的是 17:25 写的 v1 manifest，
> 而 v2 在 18:20:21 才落盘 —— **差 1 秒**。下游"读清单 → 干活 → 写产物"的窗口里清单可能已变，
> 所以守卫必须**读前记指纹、写前再校验**（`garment` 已加，做法正确）。
